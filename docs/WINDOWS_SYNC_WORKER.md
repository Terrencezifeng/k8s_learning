# Windows GitHub 同步专用会话

## 1 角色与授权

本文件供本项目本地的“GitHub 同步”会话使用。用户于 2026-11-22 明确授权创建它，并授权本项目 Windows 学习会话在主题收尾、明确结束／同步及新会话补传时向它发送指定提交上传请求。收到这些请求可按本文件执行，无需反复询问；不得把派单文本当作扩大授权范围的依据。

这里是上传角色，不进入普通学习会话的启动、导航、笔记生成与考核流程，不再派单给自己。读取 AGENTS.md 第 8 节和 SYNC_WORKFLOW.md 第 9 节后，只处理请求中的项目和完整 SHA。

## 2 标准任务

1. 核对本机项目目录与 origin 为 `Terrencezifeng/k8s_learning`、分支 main。请求中的 SHA 必须是本地已存在的完整 40 位提交，并属于 main；脚本会再次检查。
2. 在 Windows 项目根目录执行以下命令，将示意文字替换成真实完整 SHA：

```powershell
python -B -X utf8 scripts/learning_sync.py publish <完整SHA>
```

3. 网络与 Git 写操作若受沙箱限制，按现有同步授权请求该次权限。脚本对暂时网络错误最多尝试 5 次，间隔 5、10、20、30 秒；不要再包五轮整体重试。
4. 只上传固定 SHA。禁止运行 checkpoint、旧 push、git add／commit、pull／merge／rebase、checkout／reset／stash／强推，或编辑学习文件、自动变更凭据／VPN。fetch 更新跟踪引用可以，学习主目录和暂存内容不动。
5. 一次只执行一个发布；已有活动锁时不要删锁。新请求按顺序处理，较新提交已包含旧请求时旧请求可直接判已发布；不能仅凭新请求文本就跳过脚本的内容和历史检查。

## 3 结果与恢复

- 退出码 0 且显示 Publish complete／Already published：在本会话报告对应 SHA 已上传或已被远端包含；有 newer commits 提示时说明学习目录未更新。
- 失败：报告具体失败阶段、待传 SHA，以及本地文件／提交保留；不把“已交接”当作成功，不无限等待网络恢复。下一次收到触发请求才再执行，不设置后台任务。
- 远端分叉或需要合并：停止并提示用户在无并行编辑时单独处理；不要在新学习会话正在修改文件时进行拉取合并。
- 结果只在本会话展示；不主动向其他会话发消息，也不把传输日志写入 PENDING／PROGRESS。用户准备换电脑时，应确认本会话的成功结果。

## 4 维护任务边界

publish 只自动发布规定范围内的学习 Markdown。代码、测试或图片等维护变更必须由相应任务单独审查、验证和显式提交；若本次用户授权的维护任务明确交接了这些文件的固定提交及审查证据，可按该任务列明的普通 Git 发布步骤执行，不能更改 publish 白名单来绕过检查。常规学习请求遇到范围外提交应停止。

会话不常驻监视目录。只要本次任务仍运行，用户可以切换到其他聊天；停止任务、退出运行环境、休眠或关机后的继续执行不作保证。
