# 学习会话自动同步

首次确认：2026-11-03；当前时机调整于 2026-11-22。目标固定为 `Terrencezifeng/k8s_learning` 的 `main`。Mac 保持开始拉取、实质学习记录保存后提交推送；Windows 改为主题收尾等节点本地提交，由专用会话上传，详见第 9 节。同步由项目规则驱动，不是常驻服务。

## 1 时机与范围

| 时机 | 动作 | 完成依据 |
| --- | --- | --- |
| Mac 开始学习 | `pull` 后重读规则与进度 | 退出码为 0、显示 Pull complete |
| Mac 保存实质学习记录／结束学习 | `push` 提交并上传 | 退出码为 0、显示 Push complete |
| Windows 每次问答后 | 及时保存本地文件 | 本地记录已保存；不等待 GitHub |
| Windows 主题收尾、明确结束／同步／切换设备 | `checkpoint` 后向专用会话发送固定 SHA | 区分本地已提交、请求已交接与上传已成功 |
| Windows 新会话发现遗留未同步记录 | 本地检查、必要时 checkpoint，交专用会话补传；依据本地记录继续 | `status` 是本地缓存判断，不能保证远端最新 |
| 会话外使用 Typora | 先保存，下次会话按设备规则处理 | 未保存到磁盘的编辑无法同步 |

自动提交范围为根目录 `AGENTS.md`、`README.md`、`PLAN.md` 和 `docs/` 下的普通 UTF-8 Markdown 文件，支持中文路径及删除记录。代码、图片、清单和日志同样可以通过 Git 迁移，但修改这些文件时需在相应任务中检查后显式提交，不由学习记录同步脚本自动发布。目录白名单和凭据模式检测只是防误传措施，不能保证识别所有秘密；笔记中仍不得填写凭据。

不会上传 `.local/`、IDE 设置、登录状态、私钥、kubeconfig 或虚拟环境。同步不使用 `git add .`，也不会把已有手动暂存内容混入学习提交。历史 ZIP 与清单继续保持原快照。

## 2 执行方法

在 **Mac 项目根目录**执行：

```bash
python3 scripts/learning_sync.py pull
python3 scripts/learning_sync.py push
```

在 **Windows 项目根目录的 PowerShell**执行本地检查与提交：

```powershell
python -B -X utf8 scripts/learning_sync.py status
python -B -X utf8 scripts/learning_sync.py checkpoint
```

`status` 不联网，JSON 中 `remote_checked` 固定为 false，ahead／behind 仅比较缓存；`checkpoint` 不联网，只检查并提交合规 Markdown，返回完整 SHA。专用会话调用 `publish <完整SHA>` 上传，不改工作树。命令本身不会唤醒其他会话，派单由 Codex 工具完成，见第 9 节。

原 `pull` 获取远端并只允许快进；原 `push` 扫描、提交并上传，供 Mac 及明确的维护节点使用。Windows 学习中不调用这两个前台网络入口。依赖仍为 Git、Python 3.9+、提交身份和本机 GitHub 凭据，见 [Mac 说明](MAC_SETUP.md)；不把凭据写进参数或项目。

## 3 异常与恢复

| 情况 | 脚本处理 | 下一步 |
| --- | --- | --- |
| 开始时存在本地修改 | Mac pull 停止，Windows 先检查本地 | Mac 检查后 push 再 pull；Windows 对授权学习记录 checkpoint 并派单，不等待网络 |
| 远端已更新且本地有未提交修改 | 停止，不覆盖本地 | 保留双方内容，结合 diff 在单独修复步骤中合并；不要反复重试或自动选一边 |
| 两端分别产生了提交 | 停止，不自动 merge/rebase | 查看提交差异，人工决定合并方式；禁止 force push、reset --hard |
| 已有暂存文件或进行中的 Git 操作 | 停止，保留暂存／冲突状态 | 先完成或处理原操作，再重试 |
| 暂时网络失败，如超时或连接中断 | 每个 fetch／push 最多尝试 5 次，重试前分别等待 5、10、20、30 秒；耗尽后非零退出 | 保留本地文件及已生成的提交，说明实际状态；网络恢复后再 push，不能报告上传成功 |
| 认证、权限、证书校验或未知错误 | 立即非零退出，不按网络抖动重试 | 核对登录／权限或错误原因，再继续同步 |
| 疑似凭据、非 Markdown 变化、符号链接或大文件 | 停止并只报文件名，不打印可疑内容 | 检查文件及尚未推送的历史；删除当前文本不代表旧提交中的秘密消失 |
| 对应操作锁存在 | 停止，保留状态 | 本地操作锁为 learning-sync.lock，上传锁为 learning-publish.lock；确认进程结束后再处理残留锁，不自动删除活动锁 |
| 远端在推送前又发生变化 | 普通 push 拒绝 | 本地提交保留，拉取检查后处理分叉；不强制覆盖远端 |

扫描或提交在暂存后失败时，相关文件可能保留在暂存区供检查；脚本不会擅自重置它。日常建议一台电脑结束并推送成功后，再从另一台继续编辑。

若工具环境限制网络，Codex 可以在用户已授权同步的范围内申请该次网络权限；失败需明确报告，不能将“准备提交”或“本地已保存”等同于 GitHub 已更新。

## 4 实现约束与验收

- 使用现有 Git 凭据；只允许预设 GitHub origin 和单一推送目标；只在 main 执行。
- 工作树有未提交修改时不拉取覆盖，不自动 stash，不自动合并分叉，不强推。
- 自动提交前检查 Markdown 路径、UTF-8、文件大小、符号链接和常见凭据模式；推送前还检查全部未发布提交，避免只删除最新版本中的凭据却泄露历史版本。
- 本地锁保护 checkpoint／前台同步；上传锁串行化网络发布，publish 不占本地锁，允许网络等待期间产生下一章提交。前台 pull／push 同时取得两锁，避免与上传并发。锁不保护编辑器，创建 checkpoint 的短暂阶段需协调其他文件写入及 Git 暂存。
- 脚本不调用 SSH、kubectl、Docker 或任何集群组件。macOS 操作边界由项目规则明确约束。

## 8 2026-11-19 网络抖动自动重试

- 背景：用户报告 Windows VPN 偶发卡顿，要求允许多次推送。此前脚本首次网络失败即停止；现在在现有命令内部有限重试，Mac 与 Windows 共用同一行为，调用方法不变。
- 默认策略：每个 fetch／push 最多 5 次尝试（含首次）；第 2–5 次前分别等待 5、10、20、30 秒，单次 Git 命令仍有 60 秒超时。fetch 与 push 分别计数，成功后立即继续；不把整个同步流程重新执行 5 遍，也不对 add／commit 等本地操作重试。
- 可重试：进程超时、连接超时／重置／拒绝、临时域名解析失败、传输中断，以及已识别的 HTTP 408／429／500／502／503／504。只在已确认的 Git 目标上重新尝试，不调整 VPN、代理、证书校验或凭据。
- 立即停止：明确认证／权限失败、证书／主机身份校验失败、非快进和远端拒绝；没有识别为暂时网络错误的失败也停止。若同时出现网络与拒绝信息，以停止处理优先。原有分叉、暂存、白名单、凭据扫描和锁规则继续适用。
- 状态与隐私：显示下一次尝试编号及等待秒数，不输出远端原始报错、超时捕获内容或登录信息。推送响应丢失时重复发送同一提交；失败不生成额外提交、不丢弃本地内容。
- 耗尽后的处理：报告失败及本地保存／提交情况，不自动无限叠加整轮重试，不创建后台任务。下次网络恢复后仍可补推；fetch 阶段失败时可能尚未创建本地提交，必须分别说明。
- 变更与回退：仅修改同步脚本、回归测试和说明，不新增依赖或调整 CI 权限。若需回退该功能，在检查本地修改后对功能提交做普通 revert 并正常推送，保留已有学习记录与提交历史，不强推。
- 本机验证：Windows 执行 `python -B -X utf8 -m unittest discover -s tests -v`，20 项全部通过；其中新增 5 项错误分类／次数／输出检查与 2 项真实本地 Git 故障恢复测试。凭据、分叉、已有暂存及文件范围的原有测试继续通过。安全复核确认新日志不打印远端原始内容，命令使用参数列表，未扩大同步白名单或修改认证方式。

## 9 2026-11-22 Windows 按主题提交与专用会话上传

### 9.1 目标、范围与收尾标准

用户通过 Q1–Q9 确认：Windows 的 VPN 等待从学习会话移交给固定的“GitHub 同步”会话；Mac 行为保持原样。Windows 每次实质回答仍保存笔记，但不逐题联网。章节／知识主题收尾、用户明确结束／要求同步或切换设备时批量提交；下次新会话发现遗留记录也自动交接。

收尾可由用户宣布，或助手根据主要目标已覆盖、计划题目／复盘完成或明确延期、记录齐备、没有影响收尾的未解决卡点判断，并说明依据。单题完成、单节观看或助手讲解结束不单独算收尾；推送节点不改变掌握等级，也不强制用户把所有待验证实操做完。

### 9.2 学习会话的本地操作与派单

1. 开始时 `status`，读取规则和学习文件。若有上次遗留的合规记录则 `checkpoint`；若已有待传提交直接使用完整 HEAD SHA。无待传内容不派重复请求。缓存 behind 大于零或已知冲突先报告，保留双方资料。
2. 普通问答只保存文件。在触发节点，完成本次记录并在没有其他会话同时保存这些文件的短暂窗口运行 `checkpoint`。它沿用路径白名单、历史凭据检查及已有暂存保护，只作本地提交；没有新变化不会生成空提交。
3. 从 `.local/learning-sync/thread.json` 读取本机 threadId／hostId，调用 `send_message_to_thread`，传完整 SHA、触发原因及项目目录；用户已经授权本项目 Windows 学习会话向此专用会话发同步任务，不需要反复确认。发完即返回学习，不调用 wait_threads 等待网络结束。
4. 可以这样派单，将尖括号内容换成实际值：

```text
Windows 学习同步请求。用户已授权本项目向本机注册的专用会话派单。
项目：<本机项目绝对路径>
提交：<checkpoint 返回的完整 40 位 SHA>
原因：<主题收尾／明确结束或同步／新会话补传>
请按 docs/WINDOWS_SYNC_WORKER.md 只 publish 该提交；最多 5 次网络尝试。
结果留在你的会话，不编辑学习文件、不在主工作树做 pull／merge。
```

请求消息本身保存在专用会话中。即使提交后还没来得及派单就意外中断，下次 `status` 的本地领先状态仍会触发补传。新请求到达正在运行的专用会话时按其队列／跟进处理；脚本用上传锁拒绝并行发布，旧请求发现远端已包含该提交时安全结束，不回退远端。

### 9.3 上传、并发与失败结果

专用会话仅运行 `publish <完整SHA>`。它验证 SHA 属于本地 main，fetch 到跟踪引用，检查未发布提交的 Markdown 范围与历史凭据，再以固定 SHA 推送 main。全部重试沿用相同 SHA，下一章的新提交或未保存完的文件不加入这次上传。工作树和暂存区即使已有下一章内容也不被该操作修改；该会话不编辑 PENDING／PROGRESS。

若远端已包含该提交，报告已上传；远端含更新提交时同时提示本地尚未更新。若两端分叉、认证／权限失败、发现范围外变更或凭据，停止并保留，不自动改写、强推、stash 或合并。远端新内容只进入跟踪引用，学习目录不自动变化；需要时在无并行编辑的安全节点另行处理更新。

暂时网络错误每个 fetch／push 最多 5 次，等待 5、10、20、30 秒。耗尽后在专用会话报告失败和待传 SHA，任务结束；下一次触发请求再恢复，不永久循环。上传锁与本地提交锁分离，失败或完成均释放对应锁，活动锁不能自动删除。

结果分为“文件已保存”“本地已提交”“请求已交接”“目标提交已上传”。只有最后一种能说明另一台设备有机会拉取该版本；Windows 学习可先依据本地记录继续，但必须说明尚未核对远端。换到 Mac 前查看专用会话确认上传成功，再在 Mac pull。

### 9.4 本机会话注册与运行边界

用户已授权创建“GitHub 同步”专用会话，类型为本项目本地会话，使用用户默认模型。创建后将工具实际返回的 threadId、hostId、projectId 和名称保存在忽略版本控制的 `.local/learning-sync/thread.json`，不将主机绑定标识带到另一台设备。注册丢失时用 list_threads 核对同名、同项目目录的会话再恢复；重名不能猜，也不重复新建。工具不可用或交接失败时保留本地提交并说明，用户可在专用会话手动发 SHA。

专用会话由任务消息启动，本次任务结束后空闲；没有守护进程、空闲计时、定时器或永久目录监视。切换聊天不要求等待上传，但运行依赖本机和 Codex 可用；不承诺休眠、关机或停止任务后继续。上传结果只留专用会话，不向学习会话主动发消息；学习会话仅在需要确认设备切换时查询状态。

操作说明见 [Windows 专用同步会话](WINDOWS_SYNC_WORKER.md)。若需要回退，在保护本地修改后普通 revert 此功能提交；不通过强推重置学习记录。原 pull／push 继续供 Mac 使用，无新增依赖、系统后台任务或 CI 权限。
