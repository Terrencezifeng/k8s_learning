# 学习者画像与约定

确认日期：2026-10-28（Asia/Shanghai）。

- 经验：一年运维经验；已有 Linux、Docker 和部分脚本基础。
- 第一阶段目标：在自己的 K8s 实验集群中部署应用，理解资源关系，独立排查常见故障。
- 主线：用户提供的 B 站课程；结合自己的实验环境实践。
- 课程预习（2026-10-29 确认）：助手先精读 P14–P25，后续在学习会话中跟随用户报告的学习进度继续准备，便于即时答疑；预习不等于用户观看或掌握，也不表示对话关闭后自动后台阅读。入口见 [P14–P25 预习索引](video-notes/P014-P025-预习索引.md)。
- 方式：原理 → 熟悉场景类比 → 亲手实验 → 结果分析与排障 → 小问题复盘。
- 考核回答模板（2026-10-29 补充）：每次知识掌握考核都在消息最后提供可复制填写的空白模板，题号、顺序及小问与考题对应；尤其是多个知识点、多道题一起考核时不得遗漏。概念题留回答位置，实操题按需留命令、实际输出和解释位置，不预填答案；允许标记不确定、不会或未执行。
- 追问背景（2026-11-10 补充）：作答后的追问、纠错复盘及跨轮续答，要在新消息中重新给齐独立作答所需的场景、前提、参数或代码／日志片段，并完整列出本次问题及空白回答模板，保留原题号；不用翻看上文或打开链接才能答题。条件有变动时明确指出，仅追问尚需澄清的部分，不机械重考已通过内容；2026-11-16 另确认章末新场景／综合题抽查及经选择的跨章节复习可以复测，历史通过记录保留。
- 章节评估（2026-11-16 确认）：按知识主题划分，先集中确认子技能、课程范围、可复用证据和补测／抽查计划，再逐题首测，集中反馈技能图，随后补弱与复测。允许暂停、分批作答、主动请求提示或直接解释，但如实区分独立表现与有帮助表现。流程见 [章节评估](CHAPTER_ASSESSMENT.md)，报告采用 [评估模板](ASSESSMENT_TEMPLATE.md)。
- 技能图与目标（2026-11-16 确认）：书面与实操分别记 0–5 级，常规目标 4 级、5 级为进阶；未评估不等于 0，纯概念实操不适用，证据不足标待补证。确认／晋级至少两次独立检查，其中至少一次不紧接答案讲解；旧证据先核对再复用，不批量赋级。展示证据、等级和达标项数，不计算整体百分比。未达标时由用户决定继续或先补。
- 跨章节复习（2026-11-16 确认）：后续学习会话每次建议 1–2 项，用户选择后进行；一次失误先待复核，独立检查确认后再调整当前等级并保留历史证据。不设置后台提醒；Mac 只做书面复习，实操留待 Windows 明确进入实验。
- Markdown 大纲（2026-10-30 确认）：项目已有及今后的文档统一使用层级数字编号；总标题不编号，正文为 1、2、3，子标题为 2.1、2.2，更深层为 2.1.1。编号直接写进标题，新增或调整章节时同步维护；保留日期、课程 P 编号及原题号。
- 类比：Linux、Docker、脚本、infra（基础设施）运维；按需延伸到 AI 和计算机基础，每次限定在当前知识点并说明边界。
