## 3 助手补充：后续讲解采用的准确边界

**Pod 共享网络，不代表默认共享所有命名空间。** 同一 Pod 的容器共享网络与端口空间，可以用 localhost 通信；共享进程命名空间需要显式配置 `shareProcessNamespace: true`。P7 用 Docker 参数主动共享 PID 的演示，不能直接推导出 K8s Pod 默认行为。依据：[Pod 网络](https://kubernetes.io/docs/concepts/workloads/pods/#pod-networking)、[进程命名空间共享](https://kubernetes.io/docs/tasks/configure-pod-container/share-process-namespace/)。

**Docker 模拟实验帮助理解共享机制，但不等于创建了 K8s API 中的 Pod 对象。** “逻辑分组”不意味着 Pod 没有对象身份。单容器 Pod 也很常见，不需要为了凑成“容器组”强行放多个业务进去。依据：[官方 Pod 概念](https://kubernetes.io/docs/concepts/workloads/pods/)。

**CRI 是接口，containerd 等是实现相关接口的运行时；OCI 属于另一层标准。** CRI 用于 kubelet 与运行时通信；OCI 定义容器镜像、运行等规范。不要把二者记成互斥的“Docker 语言和其他运行时语言”。Docker Engine 可通过 cri-dockerd 适配到 K8s；当前集群已有 containerd，不需要照课程再安装这一适配器。依据：[CRI](https://kubernetes.io/docs/concepts/containers/cri/)、[OCI 概览](https://opencontainers.org/about/overview/)、[Docker 运行时接入](https://kubernetes.io/docs/setup/production-environment/container-runtimes/#docker-engine)。

**kubeadm 的控制平面容器与宿主机服务要分清。** 控制平面可以通过静态 Pod 运行，而 kubelet 负责在节点上管理这些 Pod；不能把课程的简化表述理解为“每个组件都只作为容器存在”。依据：[静态 Pod](https://kubernetes.io/docs/concepts/workloads/pods/#static-pods)。

以上是助手对照官方资料的补充。课程中的历史市场判断、排名、旧镜像地址和安装简化选项不作为今天的通用建议；具体需要时再核验。没有画面证据的命令不从 AI 字幕猜写成可执行命令。
