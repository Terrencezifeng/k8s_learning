# 章节评估与技能图

用户确认并接入日期：2026-11-16（Asia/Shanghai）。本流程按知识主题组织章末评估，承接现有课程、问答和实践证据；由项目 [AGENTS.md](../../AGENTS.md) 第 10 节触发。

## 1 来源与本项目适配

参考 Jane Street 的 [Socratic Tutor](https://github.com/janestreet/agent_skills/blob/master/socratic-tutor/SKILL.md)，读取日期为 2026-11-16。借鉴其子技能拆分、0–5 级描述、独立检查、追问教学和综合评估。该链接指向可变的 master；将来参考新版时重新核对，不自动覆盖本项目已经确认的规则。

原技能是持续导师流程，其 skill map 是子技能与等级展示，未定义技能依赖图的数据结构、整体百分比算法或最终考试分数线。本项目采用下述已确认适配：知识主题边界、先评估再补弱、书面与实操分列、复用历史证据、确认后抽查、一次失误先复核、学习者决定是否继续课程。等级及通过条件按第 3 节、4.3 执行，不使用主观整体掌握百分比。

完整题目背景、空白回答模板、真实证据、版本核对和设备限制优先沿用项目约定。普通答疑仍正常解释，不因出现知识问题就自动进入章末评估。

## 2 触发与范围确认

用户明确表示某个知识主题学完，或明确要求该主题的章末评估时，先读取 [学习画像](PROFILE.md)、[当前进度](PROGRESS.md)、[问答暂存](PENDING.md)、相关课程笔记和已有评估报告。仅观看位置前进、助手预习完成或环境修复成功，均不能自动触发考试或认定章节完成。

1. 按知识主题划分，如基础命令、控制器；课程正式章名和分 P 用于定位来源，预习笔记分组不自动等于完整章节。
2. 通常拆为 4–10 个可验证的子技能，窄主题可少于 4 个；宽主题先分支，再选定本次范围。用具体能力描述，例如“选对命名空间和容器并读取上一实例日志”。同一主题沿用子技能编号；拆分或合并时说明与旧编号的对应，不据此继承未验证能力。
3. 列明每项的课程位置、必要前置知识、书面目标、实操是否适用、已有证据、计划复用／补测／新场景抽查，以及判断不确定处。前置知识只用于说明后续影响，不自动扩大考试范围。
4. 将清单集中展示，允许用户逐项调整并一次确认。未确认的跳过建议不生效；用户自述和身份背景只作参考。确认范围前不出第一题，也不把旧记录批量赋为等级。
5. 默认两种适用维度均以 4 级为目标，5 级为进阶目标。若用户另定目标，在报告中记录。Mac 只启动书面部分，实操列为待验证；Windows 也只有用户明确进入实验后才开始实操。

范围、设备、目标或关键前提变化时，说明变化并确认受影响部分；不重复征求已经覆盖当前步骤的授权。

## 3 技能图与证据标准

### 3.1 等级含义

| 等级 | 表现含义 |
| --- | --- |
| 0 | 已有直接证据表明尚未形成该项认识；不能从沉默、未答或未执行推断 |
| 1 | 听说过或能识别相关概念，但尚不能解释或应用 |
| 2 | 能跟随解释、示例理解，尚不能自行完成 |
| 3 | 在提示或分步帮助下能完成 |
| 4 | 无需助手给出答案、步骤或关键提示，能独立解释、应用并核对结果 |
| 5 | 在独立完成基础上，能清楚讲授，并处理边界条件或具有迷惑性的反例 |

“理解与书面应用”依据解释、命令书写、YAML 审阅、预测和场景分析；“实操”依据用户亲手执行的命令、真实输出、验证过程和解释。书面答对不能抬高实操等级，助手代操作不计用户实操。实操是否适用在范围确认时明确，不能因为暂时没有 Windows 环境就改为不适用。

无任何评估证据填“未评估”；已观察表现但不足以确认等级填“待补证”，并描述已有表现；纯概念项实操填“不适用”。暂停、未答、不确定和未执行如实记录，不自动记错或给 0 级。不得仅凭用户身份、观看完成或助手已经讲解授予等级。

### 3.2 独立检查与等级变更

- 正式确认或上调某一维度的等级，至少需要两次支持该等级的独立检查，其中至少一次是无提示回忆或应用，且不能紧接着答案讲解。等级 4、5 的独立性要求在相应维度分别成立；5 级还须同时有边界处理和清楚讲授的证据。
- 新场景或隔开其他学习内容后的检查可以成为独立证据，但必须核对是否仍被刚给出的答案提示。换名字照抄原题、同一解题过程拆成多个小问、立即复述答案，不计作多次独立检查。
- 历史证据须有日期、原问题／操作、用户表现、帮助程度和结果，且能力范围及版本适用。符合要求即可复用；出处、提示程度不清或只有“已通过”摘要时标记待补证，不编造当时条件。
- 帮助情况逐次记录：无提示、用户自行查资料／命令帮助、助手提示、直接讲解后练习、助手代操作。查资料不自动等于有助手帮助，但本次查到了目标答案就不能作为无提示回忆证据；实操能否独立判断仍须看真实过程。
- 部分正确只认可对应评分点，保留未解决点；不替用户补全解释后算作答对。格式或排版问题与概念错误分开处理，不能把不影响语义的写法误判为能力缺失。
- 一次复评失误先保留原等级并加“待复核”标记，通过独立问题复核后再按现有证据维持或调整当前等级。不得机械减一级、改写历史结果，或依据未答／暂停降低等级。

### 3.3 展示格式

技能图以表格呈现：子技能编号、具体能力、书面等级及目标、实操等级及目标、支持证据、当前状态和下一步。初始图保留首测前的可靠证据；首测结束、等级变化、综合评估结束及用户询问时展示最新图。多项变化可合并展示，但不覆盖初始图。

分别统计书面与实操的“达标项数／适用项数”，并列出未评估、待补证、待复核项。适用但未评估的项目仍在分母中，不适用项不进入该维度分母；没有适用项时写“不适用”。保留原等级但待复核的项目暂不计入当前已确认达标项，待复核后更新。不把两个维度平均成总分，也不生成整体掌握百分比。

## 4 评估与补弱流程

### 4.1 首轮评估

按已确认的复用、补测和抽查清单逐题进行，记录首答和当时的帮助程度。一次一道题，同一场景可有必要小问；不预填标准答案、暗示或预期结论。用户可分批作答、标记不会或暂停。首轮结束前原则上只澄清题意、记录回答，不提前讲解后续题所需答案。

每条考核或追问消息包含独立作答所需的场景、对象、适用版本、前提、参数及相关片段；明确假设与真实输出的区别，保留题号，条件变化须指出。消息最后附一一对应的空白回答模板，概念题留“我的回答”，真实实操题才按需留“执行命令／实际输出／我的解释”。

用户要求提示或直接解释时立即尊重其选择，将该次表现改记为有帮助；保存帮助前的首答，相关后续题若受答案影响也注明。之后需要独立验证的点安排新场景，不把辅导后正确反填为首次独立正确。首轮结束集中展示技能图及弱项；未完成首轮时只给阶段结果。

### 4.2 针对弱项教学与复测

优先处理阻碍后续理解的弱项，结合 Linux、Docker、脚本及运维经验追问原因、预测结果、辨别错误或迁移到新场景。答错时先用更窄的问题帮助定位矛盾；连续 2–3 次仍卡住时简短讲解，不无限追问。用户随时可要求直接解释、降低难度、暂停或继续课程。

讲解后换角度练习，练习结果与独立复测分别记录。已可靠通过的部分不机械重考；范围确认中已批准的新场景／综合题抽查可以使用，但明确标为复测，保留原通过结论。补弱不能悄悄增加未确认的新专题。

### 4.3 综合评估与通过条件

综合评估覆盖本次范围内每个子技能，至少为每项提供一个可单独判断的检查点，并包含至少一道跨技能综合问题；一题可以覆盖多个技能，须分别判定。可复用本轮已完成且满足独立性与覆盖要求的新场景综合题，不为满足流程重复出相同题。

某一维度达标，须该维度所有适用子技能达到确认目标、满足证据要求，并完成对应综合检查；存在未评估、待补证或待复核项时，列明缺口。书面达标但实操待验证，只报告“书面达标，实操待验证”；只有两种维度所有适用要求均满足，才报告主题达标。目标 5 的边界处理与讲授也须有证据，不采用另设总分及格线。

不达标时说明具体弱项、影响及补学建议，由用户选择继续或先补；不能以全部过关为条件强行阻断下一章。评估暂停或尚缺实操时标记进行中／部分完成，不能等同考试失败。

## 5 跨章节复习与结果维护

在后续实际学习会话中，结合距离上次独立验证的时间、后续章节所需基础和曾经薄弱的技能，建议复习 1–2 项。列出建议、依据和不确定处，用户选择后才出题；不设置后台提醒，不在每轮回答中重复催促。没有统一的自动到期天数，记录下一次适合复习的学习场景或用户另定的时间。

复习使用新场景，先保留无提示表现，再按 3.2 处理失误与复核。只写“最近有待复核证据”，不能把历史已通过改成从未掌握。新的等级与记录更新要告知用户，实际学习时长仍以用户提供为准。

## 6 报告、续接与同步

- 使用 [评估模板](ASSESSMENT_TEMPLATE.md)，在范围确认并实际开始评估时创建 `docs/learning/assessments/YYYY-MM-DD-主题.md`；同日重复评估用不同后缀，跨会话继续同一评估时保留同一文件和阶段日期。目录入口为 [评估记录](assessments/README.md)。配置机制时不创建虚构的已评估报告。
- 报告保存确认范围、初始／最终技能图、检查点覆盖、首答、帮助情况、证据链接、等级变化、弱项及下一步。报告中的问答保留问题原意和完整背景；未询问的问题不得写成用户提问。
- 每次实质回答或阶段结束及时保存报告，在 [PENDING.md](PENDING.md) 追加有日期的简短事件和链接，并更新 [PROGRESS.md](PROGRESS.md) 的当前状态及最新报告入口。详细证据以报告或已引用的原始记录为准，不复制多份可独立修改的等级账本。
- 初始迁移只引用旧证据，不批量赋级；发现过时摘要时依最新用户作答修正当前总览，保留带日期的历史过程。新增评估不自动推进观看位置，也不撤销旧的书面通过事实。
- 评估报告可随问答持续保存，时长未知不妨碍保存；它不等于一份已经满足半小时条件的正式 session 记录。正式归档仍使用 [学习记录模板](SESSION_TEMPLATE.md) 和原有时长规则，并链接评估报告。
- 每次回答后及时保存本地报告，上传按 AGENTS.md 第 8 节的设备规则：Mac 保存实质记录后 push；Windows 在主题／评估收尾、明确结束／同步等节点本地提交并派给专用会话，不逐题等待上传。未完成评估不因推送需要而判为收尾；失败时区分本地保存／提交、已交接和远端已收到。Markdown 已在白名单内，Git 同步文件，不复制全部聊天历史或全局 skill。

## 7 接入边界

此机制由本项目规则和文档驱动，不要求安装全局 Socratic Tutor 技能。Mac 不连接集群或要求真实集群输出；Windows 实操仍由用户明确启动、亲手操作，沿用独立命名空间及现有版本核对方式。任何新题中的对象、日志、YAML 或结果若为假设，必须明示；未运行的命令不生成实际输出。
